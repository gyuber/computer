# 신품 완제품 검토

상품 하나를 놓고 **"이 사람이 이 제품을 이 값에 사도 되는가"**를 답하는 스킬이다.

중고 매물 판단(`used-pc-listing-check`)과는 보는 지점이 다르다. 신품은 채굴이나 우회 인증 걱정이 없는 대신, **고칠 수 없는 사양(온보드 램)**과 **가격 착시(윈도우 미포함, 카드할인가)**와 **이름만 새것인 구형 부품**이 함정이다.

## 작업 순서

### 1. 프로필을 정한다

같은 제품이 누가 쓰느냐에 따라 정답이거나 낭비다. `references/profiles.md`에 정해진 프로필이 있다.

- 대화에서 누구 것인지 드러나면 해당 프로필을 쓴다. 다시 묻지 않는다
- 프로필에 없는 사람이면 용도·휴대 여부·예산을 한 번만 묻는다. 그마저 애매하면 "일반 사무용, 휴대함" 기준으로 가정하고 가정을 밝힌다
- 사용자가 방향 자체를 다시 정하려 하면 `pc-buying-brief`로 넘긴다

### 2. 상품 정보를 확정한다

링크를 받으면 상품 페이지를 읽는다. 읽을 수 없으면 모델명으로 검색한다. **상품명 문구가 아니라 상세 스펙표에서** 다음을 확정한다.

| 항목 | 확정할 것 |
|---|---|
| 모델 코드 | 정확한 전체 코드 (예: `16Z90U-GA5xK`). 같은 이름에 구성이 여러 개다 |
| CPU | 정확한 모델명과 세대 |
| 램 | 용량, **온보드인지 슬롯인지**, 빈 슬롯 유무 |
| SSD | 용량, NVMe 여부, 추가 슬롯 유무 |
| OS | **윈도우 포함 여부와 에디션(Home/Pro)** |
| 무게·배터리 | 노트북이면 kg, Wh |
| 단자 | USB-C의 화면 출력·충전 지원(썬더볼트 / DP Alt / PD) |
| 판매 경로 | 국내 정품인지, 해외직구·병행수입·리퍼·전시인지 |

모델 코드 해독과 CPU 세대 판별은 `references/traps.md`를 읽는다. **스펙표와 상품명이 다르면 스펙표를 믿고, 불일치 자체를 보고한다.**

### 3. 탈락 규칙을 적용한다

여기 걸리면 가격이 좋아도 권하지 않는다. 사고 나서 돈으로 고칠 수 없거나 고치는 비용이 차액보다 크다.

| 항목 | 탈락 | 이유 |
|---|---|---|
| 램 | 노트북 온보드 램이 프로필 기준 미만 | 평생 그 용량. 증설 불가 |
| SSD | 256GB 이하 (추가 슬롯이 있어도) | 윈도우와 업무 프로그램만으로 빠듯하고, 증설은 번거롭고 비용이 듦. 신품을 256GB로 사는 것 자체가 잘못된 구성 선택 |
| CPU | 구형 리브랜드(`references/traps.md`), 3급(i3·라이젠 3·셀러론·펜티엄·N시리즈) | 이름은 신형, 속은 2~4년 전 |
| 그래픽 | 데스크탑에 내장그래픽 없는 CPU(인텔 `F`, 라이젠 5000번대 이하 G 없는 모델)인데 그래픽카드도 없음 | 화면이 안 나옴 |
| 판매 경로 | 해외직구·병행수입인데 국내 AS 불가 | 노트북 고장 시 수리 경로가 없음 |
| OS | 프로필이 한글(hwp)을 요구하는데 맥 | 한글 호환 문제 |

감점은 탈락과 구분해 적는다. 프로필 대비 오버스펙(외장 RTX, H·HX CPU, 64GB 램), 무게 초과, Windows Home(프로필이 Pro를 요구할 때), 화면 출력이 안 되는 USB-C 등이다.

### 4. 가격을 검증한다

**시세를 기억으로 쓰지 않고 검색한다.** 같은 **전체 모델 코드**로 다나와 최저가를 찾는다. 이름만 같고 구성이 다른 모델을 비교하면 결론이 틀린다.

가격은 세 가지로 나눠 적는다.

- **표시가**: 아무 조건 없이 사는 값
- **조건부가**: 특정 카드, 쿠폰, 멤버십이 필요한 값. 조건을 적는다
- **실질 총액**: 윈도우가 없으면 윈도우 값, Home이고 프로필이 Pro를 요구하면 Pro 업그레이드 값을 더한 값. 이것으로 후보끼리 비교한다

"최대 혜택가"는 대개 여러 조건이 겹친 값이다. 사용자가 실제로 받을 수 있는지 확인되기 전에는 표시가 기준으로 판단한다.

### 5. 판정한다

**진행 / 조건부 진행 / 탈락** 중 하나를 고른다. 회피하지 않는다.

- **진행**: 탈락 없음, 감점이 사소함, 가격이 최저가 근처
- **조건부 진행**: 확인 안 된 항목이 하나 있거나, 가격이 최저가보다 의미 있게 비쌈. 무엇이 확인되면 진행인지 적는다
- **탈락**: 탈락 규칙에 하나라도 걸림. 대안 방향(같은 라인의 상위 구성 등)을 한 줄로 준다

### 6. 기록한다

프로필에 **추적 이슈**가 적혀 있고 작업 디렉터리가 그 저장소면, 판정 뒤에 결과를 이슈 코멘트로 남길지 묻는다. 사용자가 미리 "기록까지 해"라고 했으면 묻지 않고 남긴다.

```bash
gh issue comment <번호> --body-file <파일>
```

코멘트는 아래 출력 형식을 그대로 쓰되 **상품 링크, 판정일, 판정 시 가격**을 포함한다. 가격이 움직이므로 날짜가 없는 가격은 나중에 쓸모가 없다. 공개 저장소일 수 있으므로 **사용자의 이름, 직장, 개인 정보는 쓰지 않는다.**

## 출력 형식

### 상품 하나

```
## [제품명] — [진행 / 조건부 진행 / 탈락]

| 항목 | 이 제품 | 기준 | |
|---|---|---|---|
| 램 | 32GB 온보드 | 32GB | ✅ |
| ... | | | |

**가격** 표시가 / 조건부가(조건) / 실질 총액 — 다나와 최저가 대비 ±N원 (YYYY-MM-DD)

**걸리는 점** (탈락·감점. 없으면 생략)

**좋은 점** (프로필 기준으로 실제 값어치가 있는 것만)

**확인할 것** (미확정 항목과 판매처에 물을 문구)
```

### 여러 개

후보를 같은 표에 열로 놓고 실질 총액을 맨 아래 줄에 둔다. 탈락은 표에서 빼고 한 줄 사유만 남긴다. 마지막에 **1순위를 하나 고르고** 이유를 한 단락으로 쓴다. 차이가 작으면 "이 차이에 돈을 더 낼 가치가 있는가"로 정리한다.

## 자주 나오는 판단 패턴

**데스크탑과 노트북 후보가 섞여 오면** 형태별로 따로 순위를 매기고, 마지막에 형태 간 비교는 실질 총액과 프로필의 "이 프로필에서 중요한 것"으로만 한다.

**같은 이름, 다른 구성.** "2026 그램 16"은 CPU, 램, SSD, OS 조합으로 여러 개다. 사용자가 링크 없이 이름만 주면 원하는 구성을 프로필에서 역산해 **정확한 모델 코드를 제시**하고, 그 코드로 검색하게 한다.

**온보드 램은 사는 순간 확정이다.** 노트북에서 16GB 모델이 32GB보다 수십만원 싸 보여도, 프로필이 32GB를 요구하면 탈락이다. 나중에 늘릴 방법이 없다는 것을 한 문장으로 말한다.

**윈도우 미포함 모델은 싸 보인다.** 그램 `ZD`처럼 OS가 없는 모델은 윈도우 값을 더하면 포함 모델과 비슷하거나 더 비싸다. 실질 총액으로만 비교한다.

**오버스펙은 감점이다.** 사무용 프로필에서 외장 그래픽, H·HX CPU는 성능이 아니라 무게, 소음, 배터리 손해다. "좋은 제품이지만 이 사람에게는 비싸다"를 분리해서 말한다.

**모니터 연결을 확인한다.** 사무실에서 모니터에 꽂아 쓰는 프로필이면 USB-C 하나로 화면과 충전이 되는지(썬더볼트 또는 DP Alt + PD)가 매일의 편의를 가른다.

**소프트웨어 번들은 따로 계산한다.** 오피스와 한글은 대개 별도 라이선스다. 번들로 들어 있으면 가산점이지만, 체험판인지 영구 라이선스인지 확인한다.

## 하지 말 것

**가격을 기억으로 쓰지 않는다.** 판정할 때마다 검색한다.

**결정된 방향을 매번 흔들지 않는다.** 프로필에 정해진 형태(데스크탑·노트북)와 기준 안에서 판단한다. 프로필이 두 형태를 다 열어 두었으면 들어온 상품의 형태에 맞는 기준표를 쓰고, 다른 형태를 권하지 않는다. 프로필 자체를 바꿔야 할 새 정보가 나왔을 때만 말한다.

**완벽한 제품을 기다리게 만들지 않는다.** 진행 판정이 나온 제품이 있으면 그것을 기준선으로 삼고, 이후 후보는 "기준선보다 나은가"로만 판단한다.
